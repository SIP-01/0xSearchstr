# Improvement Deep-Dive — 0xSearchstr — 2026-10-21

Scope: SIP-01 search engine frontend (+ `backend/` relay helpers). Files read: `package.json`, `src/lib/providers/web-index.ts`, `src/AppRouter.tsx`, `src/hooks/useAdminAccess.ts`, `.github/workflows/deploy.yml`; code searches for `autocomplete`, `git clone`, `validateEvent`.

## Top recommendations (ranked, with effort S/M/L)

1. **Backport the security fixes from 0xPresearchstr PR #2 (merged 2026-10-14, 90 files, +2658/−1316; catalogued in `docs/CODE-REVIEW.md`, 19 fixes) — most were never ported to this repo (S/M).** Verified still-open in 0xSearchstr main:
   - **d-tag squatting (P1):** `src/lib/providers/web-index.ts` verifies the `d↔u` hash binding only for the *selected winner* after grouping, not for every candidate before grouping. An attacker can squat a victim URL's `d` and win the group. Fix: verify each candidate event before it enters the group (as done in 0xPresearchstr).
   - **Clone-command shell injection (P1):** `RepoView.tsx` still builds an unquoted `git clone ${repo.webUrl}` copyable command (confirmed via code search). Quote/escape as in PR #2.
   - **Revoked moderators stay active (P1):** `src/hooks/useAdminAccess.ts` still selects the latest admin event by `created_at` without the PR #2 revocation-aware selection.
   - **Broken GH Pages routing:** `src/AppRouter.tsx` has no `basename` — repo is served at `/0xSearchstr/` so deep links break. PR #2 fixed the equivalent for 0xPresearchstr.
   - **`deploy.yml` never runs tests** (`npm install && npm run build` only) — the same gap that let a broken `npm test` go unnoticed in 0xPresearchstr. Switch to `npm ci && npm test && npm run build`.
   - **Likely also applicable (same code lineage, not individually re-verified):** provider-search dedup dropping query params, provider-switch stale cache keys, account-switching relay leak, Nostra JSON crash, engine auto-enable wiping defaults.
2. **Resolve the 0xSearchstr ↔ 0xPresearchstr duplication decisively (M).** The two repos share the entire provider stack (`web-index.ts`, `community.ts`, `relay-discovery.ts`, hooks, UI). 0xPresearchstr has had the security pass; this repo hasn't. Concrete merge/deprecate path:
   1. **Now (S):** cherry-pick PR #2's fork-independent fixes (items above; skip ads/staking-removal diffs) into 0xSearchstr.
   2. **Next (M):** extract the shared search core (`src/lib/providers/*`, `webIndex`, hooks) into `@sip01/search-core`, versioned, consumed by both apps.
   3. **Decide (S governance):** either keep 0xSearchstr as the "lite" frontend on the shared core, or archive it with a README pointer to 0xPresearchstr. Don't leave two unfixed copies live — every future fix otherwise lands in one place only, as just happened.
3. **Branch protection + PR reviews (S).** `main` unprotected; direct-to-main pushes observed.

## Ecosystem alignment notes

- **NIP-50 autocomplete:** added upstream 2026-06-06 (#2357), reverted 2026-06-09 (6882751). Verified org code search: no reliance — only HTML `autoComplete="off"` attributes. Safe. Keep it that way: don't gate any UX on `autocomplete:` until it lands upstream for real.
- **NIP-50 search usage:** providers query `search` filters against NIP-50 relays — current spec's operators (`domain:`/`site:`-style, `language:`) are stable; no `autocomplete`. What relays expect: a `search` string plus standard filter fields; extensions are SHOULD-level per the spec repo's own v1.2 re-audit, so degrade gracefully when a relay ignores them (current behavior — keep).
- **NIP-01 this week (#2504/#2511):** audit every dynamically built filter before sending — empty array fields now explicitly match nothing, and empty lists shouldn't be sent. Check `community.ts` (builds `filters: NostrFilter[]` dynamically) and relay-discovery: if a discovery round returns zero relays, skip the REQ rather than sending empty/blank filters.
- NIP-65 outbox-model fit: account/relay handling had a known leak bug (PR #2 #16); after backport, consider NIP-65 read/write relay lists for user relay persistence. M.
